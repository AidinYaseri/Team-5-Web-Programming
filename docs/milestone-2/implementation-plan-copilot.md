# Filter pets by species, age and availability — implementation plan

## Understanding
Implement server-side filtering for GET /api/pets so clients may request pets by species, maximum age and availability. The API accepts optional query parameters and returns a JSON array of Pet DTOs. Filtering logic belongs to the domain service (IPetService.SearchPets) and an in-memory service will be added until EF Core exists.

## Assumptions
- Project stays synchronous for this feature: SearchPets returns List<Pet>.
- The team-approved shapes are used: PetSearchCriteria in Animal.Domain.Models; PetSearchQuery and PetResponse DTOs in Animal.API.Contracts.
- Controller model-binding + [ApiController] will provide automatic ValidationProblem responses for bad inputs.
- The work will be done on the Copilot_instructions branch and merged to main via PR.

## Approach
Add a domain search contract (PetSearchCriteria) and extend IPetService with SearchPets(PetSearchCriteria). Implement an InMemoryPetService in Animal.Data/Services seeded with example pets; register it as a singleton in Program.cs. Add DTOs in Animal.API/Contracts to separate API concerns from domain models and implement a PetsController that binds PetSearchQuery from the query string, validates it via data annotations, maps to PetSearchCriteria, calls IPetService.SearchPets and returns PetResponse DTOs sorted by Id ascending. Add unit tests for the in-memory service and integration tests for the endpoint using WebApplicationFactory<Program>.

## Risks & Open Questions
- Interface changes: adding SearchPets modifies IPetService API surface. No implementation exists on main now, so low merge friction, but coordinate with other contributors if they add IPetService implementations concurrently.
- DI lifetime: singleton for seeded in-memory service is chosen; when EF implementation replaces it, ensure behavior parity.
- Tests must use ConfigureTestServices to inject the in-memory service for integration tests and include one test using the real Program.cs registration.
- PNG generation: repo has .mmd sources; confirm whether PNGs are generated by CI or should be committed manually.
